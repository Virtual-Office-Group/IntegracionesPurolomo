Los pedidos de venta de empleados son una funcionalidad que permite a los empleados realizar pedidos de productos o servicios a través de un sistema integrado con Business Central. Esta guía proporciona información sobre cómo integrar y consumir los recursos relacionados con los pedidos de empleados, incluyendo la suscripción a webhooks, el consumo de listas de precios y la creación de pedidos.

## Recursos para pruebas

Para facilitar la integración y las pruebas de los webhooks de Business Central, está disponible un espacio de trabajo en Postman. Esto permite interactuar con la API sin necesidad de desarrollar código de cliente de manera inmediata.

# Consumo de maestros de datos

## Consumo lista de precios de ventas

**Suscripción del recurso por webhook**

```json
POST
https://api.businesscentral.dynamics.com/v2.0/{{TenantID}}/{{enviromentName}}/api/virtualOfficeGroup/integration/v1.0/subscriptions
Content-Type: application/json
Authorization: Bearer {access_token}
body
{
  "notificationUrl": "%UrlNotificationId%",
  "resource": "virtualOfficeGroup/integration/v1.0/companies({{companyId}})/salesPriceLists",
  "clientState": ""
}
```

<Aside type="caution">
La suscripción de lista de precios de venta se gestiona a través de una API personalizada. Para realizar la solicitud de suscripción, se debe utilizar la siguiente estructura de URL en el endpoint:

```text 
POST > https://api.businesscentral.dynamics.com/v2.0/{{TenantID}}/{{environmentName}}/api/virtualOfficeGroup/integration/v1.0/subscriptions
```
</Aside>

**Consumir endpoints**

Para consultar manualmente las listas de precios de venta, puedes consumir el endpoint personalizado de Business Central.
```json
GET 
https://api.businesscentral.dynamics.com/v2.0/{{TenantID}}/{{enviromentName}}/api/virtualOfficeGroup/integration/v1.0/companies({{companyId}})/salesPriceLists
Content-Type: application/json
Authorization: Bearer {access_token}
```

## Creacion de pedidos de empleados

para crear un pedido de empleado, se debe realizar una solicitud POST al endpoint correspondiente en Business Central. A continuación se muestra un ejemplo de cómo estructurar la solicitud:

```json 
POST
https://devnamespacevog.servicebus.windows.net
Header{
  Content-Type: application/json
  Authorization: Bearer {SharedAccessSignature}
  companyID: {companyID}
  environment: {environment}
  operationType: "POST"
  requestId: {requestId}
}
body
{
    "locationCode": "ALMACEN 1",
    "customerNumber": "10000",
    "orderDate": "2025-05-25",
    "employeeSalesOrderLines": [
        {
            "itemNo": "1012",
            "quantity": 45,
            "unitPrice": 14,
            "lineDiscountAmount": 1
        },
        {
            "itemNo": "1013",
            "quantity": 45,
            "unitPrice": 14,
            "lineDiscountAmount": 1
        },
        {
            "itemNo": "1014",
            "quantity": 45,
            "unitPrice": 14,
            "lineDiscountAmount": 1
        }
    ]
}
```

#### Campos requeridos

##### Encabezado

| Campo | Tipo | Descripción |
|-------|------|-------------|
| locationCode | string | Código de la ubicación desde donde se realiza el pedido. |
| customerNumber | string | Número del cliente asociado al pedido. |
| orderDate | string | Fecha en la que se realiza el pedido, en formato YYYY-MM-DD. |

#### lineas

| Campo | Tipo | Descripción |
|-------|------|-------------|
| itemNo | string | Número del artículo que se está solicitando. |
| quantity | number | Cantidad del artículo que se está solicitando. |
| unitPrice | number | Precio unitario del artículo. |
| lineDiscountAmount | number | Monto de descuento aplicado a la línea del pedido. |
